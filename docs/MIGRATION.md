# Переезд на прод

_Последнее обновление: 2026-08-03_

Уходим с Vercel + Supabase на свой сервер в РФ. Причины: 152-ФЗ (персональные данные клиентов нельзя хранить за рубежом — сейчас Supabase в Лондоне), цена, и заодно чинится неудобная архитектура чтения каталога (см. «Архитектурный фикс» ниже).

## Фазы

### Фаза 0 — уточнить у заказчика (блокирует старт)
- Доступ к nic.ru и Timeweb — домен в WHOIS записан на «частное лицо», нужно понять, кто это и есть ли туда доступ
- Есть ли в старом Laravel-сайте живые клиенты/заказы, которые важно сохранить
- Статический ли IP у сервера 1С в офисе — от этого зависит, ставим ли IP-allowlist на приёмные эндпоинты

### Фаза 1 — сервер (Selectel, без риска для текущего сайта)
- VDS 2-4-50: 2 vCPU / 4 ГБ / 50 ГБ NVMe — 650 ₽/мес
- SSH только по ключу, ufw (наружу только 80/443), fail2ban, автообновления ОС
- Docker: контейнер `app` (Next.js) + контейнер `db` (Postgres, свой volume) — падение сайта не тронет базу
- Ежедневный `pg_dump` → Selectel S3, с первого дня
- Определить процесс деплоя (см. раздел «Как обновлять сайт» ниже) — сейчас его нет, это часть фазы 1

### Фаза 2 — данные и код (без риска для прод-сайта)
- Дамп базы Supabase → восстановление в Postgres-контейнер на Selectel
- `lib/db-catalog.ts`: 5 функций чтения каталога — с Supabase-клиента на Prisma, `lib/supabase.ts` удалить
  - Именно сейчас, не раньше: раньше архитектура специально разъехалась на два способа доступа к БД из-за бага «Prisma + пул соединений Supabase зависает на второй транзакции». На своём сервере (не serverless, без стороннего пула) причина бага исчезает — фикс архитектуры безопасен только вместе с переездом
- Полное тестирование на новом сервере — по IP/тестовому адресу, прод ещё на Timeweb

### Фаза 3 — приём от 1С (параллельно с фазой 2)
- `/api/products` (POST, приём CSV) и `/api/orders` (GET, выгрузка заказов) уже реализованы — добавить rate-limit, IP-allowlist (если есть статический IP)
- Новые длинные `SYNC_LOGIN` / `SYNC_PASSWORD`
- Алерт в Telegram, если 1С не присылала данные N часов (бот уже используется для заказов/броней — просто добавить проверку)
- В самой 1С настроить `HTTPСоединение`/`HTTPЗапрос` на боевой адрес — включать только после фазы 4

### Фаза 4 — переключение домена (единственный рискованный момент, короткий)
- Снизить TTL DNS-записи заранее (за 1-2 дня)
- В панели Timeweb (или переносом NS) сменить A-запись на IP Selectel-сервера — регистратора не трогаем
- Сразу выпустить SSL-сертификат (Let's Encrypt)
- Проверить сайт вживую, включить 1С на боевой адрес

### Фаза 5 — стабилизация
- 1-2 недели держим Timeweb-хостинг нетронутым как путь отката
- Следить, что 1С стабильно синхронизируется и заказы доходят
- Отключить старый Timeweb-хостинг и Supabase-проект

## Стоимость

~650 ₽/мес (сервер + БД + бэкапы на Selectel) вместо текущей связки Vercel + Supabase. Домен уже оплачен до июля 2027, отдельно платить за него сейчас не нужно.

Взвешивали и более дешёвые/дорогие варианты:
- Всё на одном сервере без Docker — 400 ₽/мес, но баг в коде сайта потенциально может утянуть за собой и БД
- Раздельные сервера (VPS под сайт + managed БД отдельно) — ~1190 ₽/мес, полная физическая изоляция, имеет смысл при заметном росте нагрузки
- Timeweb вместо Selectel — тот же уровень (VDS с root+Docker) стоит там 882-1062 ₽/мес, дороже без технических преимуществ — оставили только под домен

## Как обновлять сайт дальше

**Локальная разработка → прод.** Правки сначала делаются и проверяются локально (`npm run dev`), и только потом попадают на боевой сайт — не наоборот.

**Как просить правки.** Формулируете задачу в сессии с Claude Code — что изменить и зачем. Для нетривиальных задач Claude сначала предлагает короткий план (какие файлы, что создаётся), и только после вашего согласия пишет код — не наоборот.

**Git и деплой.**
- Claude коммитит только когда вы явно просите — сам по себе ничего не пушит и не деплоит
- Сейчас (на Vercel) деплой происходит автоматически при пуше в git
- После переезда на Selectel деплой так с ходу работать не будет — нужен свой процесс (простой вариант: заходите по SSH, `git pull` + `docker compose up -d --build`; более удобный — небольшой деплой-скрипт). Это нужно решить и настроить в фазе 1, до переключения домена

**Что Claude не может сделать сам.** Всё, что требует реальных аккаунтов/денег/доступов — регистрация VPS на Selectel, оплата, настройка DNS в панели регистратора, настройка выгрузки в самой 1С — это делаете вы (или тот, у кого есть доступ). Claude готовит скрипты/конфиги и объясняет шаги, но не может завести аккаунт или нажать «оплатить» за вас.

**Кто следит за инфраструктурой после переезда.** Бэкапы и автообновления сервера настраиваются один раз в фазе 1, дальше работают сами — но стоит периодically проверять, что бэкапы реально создаются (не только что cron настроен). Алерт в Telegram о том, что 1С давно не синхронизировалась, — единственный сигнал, что что-то сломалось, без него можно не заметить проблему днями.

**Один совет на будущее.** Как и с базой данных: если в процессе работы сайта возникнет ещё какой-то «костыль ради срочного фикса» (как в своё время с Supabase) — стоит проговорить в моменте, что это временное решение, и вернуться к нему явно, а не забыть, почему код выглядит именно так.
